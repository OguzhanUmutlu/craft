# Craft Roadmap & Phase Tracker (`todo.md`)

This roadmap organizes engineering phases into a strict **Future-Current-Done** lifecycle. Each item is an autonomous phase containing a 5–10 line technical specification outlining its objectives, architecture, prerequisites, and trade-offs. Once completed, phases permanently transition into the Done category.

---

## Current Phase

### Phase 7: Dynamic Resource Optimization, Auto-Scaling & Modpack Distribution
Phase 7 introduces intelligent memory allocation, dynamic GC tuning, and CurseForge/Modrinth/FTB modpack deployment automation. An automated memory profile optimizer evaluates system RAM, JVM generational ergonomics, and player caps to dynamically compute `-Xms` and `-Xmx` boundaries. A modpack installer engine (`craft modpack install <id>`) parses server pack manifests, resolves missing dependencies, and sets up override directories without manual file manipulation. Dynamic auto-scaling will allow idle server hibernation with packet-triggered wake-up via port-listening proxies, reducing CPU and memory overhead across multi-tenant server nodes. Automated testing and security sandboxing will validate pack downloads against checksum manifests before execution.

## Future Phases

### Phase 8: Multi-Tenant Role-Based Access Control, Audit Trails & Web Dashboard
Phase 8 introduces enterprise multi-tenant administration, granular role-based permissions (RBAC), and persistent cryptographic audit logging. A lightweight embedded web dashboard will serve administrative analytics, real-time live console feeds, and file browsing without external hosting dependencies. Role policies (SuperAdmin, ServerOperator, BackupAuditor, Viewer) will restrict access to destructive subcommands (`rm`, `fix --force`, `restore`, `exec`). All administrative invocations across CLI, IPC, and WebSockets will append HMAC-signed entries to an immutable audit trail (`audit.log.zst`) for compliance forensics. Automated session revocation and multi-factor authentication (TOTP) will safeguard remote control surfaces.

## Done Phases

### Phase 6: Enterprise Telemetry, Webhooks & Remote Gateway
Phase 6 delivered production-grade telemetry, event-driven webhooks, and an authenticated remote gateway. An asynchronous dispatcher (`WebhookDispatcher`) formats structured payloads for Discord rich embeds, Slack blocks, and generic JSON with pure-Rust HMAC-SHA256 request signatures (`X-Craft-Signature`) across critical operational events (`ServerCrash`, `AutoRestart`, `CircuitTrip`, `BackupComplete`, `StorageExhaustion`, `ServerStart`, `ServerStop`). A Prometheus-compatible `/metrics` endpoint collects real-time host hardware metrics via `sysinfo` and per-server telemetry including process status, CPU, RSS memory, player counts, query latencies via SLP/RakNet/A2S, crash counts, and circuit breaker states. An authenticated HTTP and WebSocket gateway (`/ws/console`) streams live server logs and injects stdin commands with constant-time Bearer token verification, prefix buffer replay (`PrefixedStream`), and sliding-window rate limiting. A background storage exhaustion monitor audits disk space every 5 minutes and dispatches alerts upon low storage thresholds (<10% or <5GB). CLI management commands (`craft webhook`, `craft gateway`) enable full endpoint configuration, token rotation, and metrics extraction. All 210 workspace tests and compiler checks (`-D warnings`) passed cleanly with zero warnings.

### Phase 5: Plugin & Mod Lifecycle Automation and Dependency Resolution
Phase 5 delivered comprehensive plugin and mod lifecycle automation and recursive dependency resolution across Bukkit, Paper, Velocity, BungeeCord, Fabric, Quilt, and Forge/NeoForge. Pure-Rust bytecode manifest inspection (`inspect_jar_manifest`) parses `plugin.yml`, `paper-plugin.yml`, `fabric.mod.json`, `quilt.mod.json`, `neoforge.mods.toml`, `mods.toml`, `velocity-plugin.json`, and `bungee.yml` in memory without JVM dependencies. A semantic compatibility engine (`evaluate_compatibility`) validates platform loaders, semver Minecraft bounds, and Bukkit `api-version` requirements. Automated dependency resolution (`resolve_missing_dependencies`) normalizes known ecosystem aliases (e.g. `vault`, `protocollib`, `luckperms`, `fabric-api`) and recursively fetches missing libraries via Modrinth (`get_latest_compatible_file`). An update checker (`check_server_updates`) calculates SHA-512 hashes and queries Modrinth batch update APIs, while `apply_atomic_update` provides atomic hot replacement with `.jar.upgrade_bak` rollback guards and non-destructive trash archival. Diagnostic doctor audits (`craft plugin doctor`, `craft mod doctor`) perform pre-boot health verification of duplicate IDs, missing dependencies, and API version mismatches. All 187 workspace tests and `-D warnings` checks passed cleanly.

### Phase 4: Ecosystem, Multi-Server Clusters and Remote Federation
Phase 4 delivered decentralized multi-server orchestration and cross-node server migration across federated machines over SSH. `craft migrate <server> --to <remote-alias>` was implemented with `ServerMigrator`, packaging servers into atomic `.tar.zst` archives, computing streaming SHA-256 digests, uploading via SFTP to `~/.craft/staging/`, validating checksums on the remote host (`sha256sum`, `shasum -a 256`, or OpenSSL), unpacking into `~/.craft/servers/<name>`, registering in remote `servers.toml`, and safely trashing local source folders via `TrashManager::trash_path`. Multi-server cluster orchestration (`craft cluster`) was introduced, backed by `~/.craft/clusters.toml` with `fs2` advisory file locks on `clusters.lock`. A topological DAG dependency resolution algorithm (`resolve_startup_order`) resolves startup sequences with cycle detection, prioritizing backend/lobby nodes before proxy routers, while `resolve_shutdown_order` enforces reverse teardown. Proxy routing automation (`craft cluster sync-routing`) synchronizes upstream endpoints into Velocity (`velocity.toml`) and BungeeCord (`config.yml`). All 185 workspace tests and strict `-D warnings` checks passed cleanly.

### Phase 3: Observability, Live Console and TUI Ergonomics
Phase 3 expanded live console observability and diagnostic forensics across Craft and ModalX. `run_virtual_console` was upgraded with an interactive `/` search and regex filter engine (`ConsoleFilter`), isolating matching log lines in real-time, displaying live match counters, and highlighting query terms with bold ANSI contrast without interrupting incoming daemon streams. Viewport freeze and pause scroll lock via Spacebar (`is_paused`) was implemented, allowing operators to halt viewport scrolling during live crashes and navigate historical frames while logs continue accumulating in memory and on disk. Real-time log level syntax styling (`colorize_log_line`) was added for `[FATAL]`, `[ERROR]`, `[WARN]`, `[INFO]`, `[DEBUG]`, and stack trace frames while preserving border alignment. A diagnostic export command (`craft log export <server>`) was authored, bundling `latest.log`, `console.log`, crash dumps, sanitized configs (`redact_sensitive_config`), and machine telemetry into a compressed `.tar.zst` archive. All 160 workspace tests passed cleanly.

### Phase 2: Automated Operations, Backups and Resilience
Phase 2 delivered background automated operations inside `craft-daemon` without external host cron dependencies. An in-process 5-field cron parser and interval evaluator was implemented alongside `DaemonScheduler`, triggering zero-downtime RCON-synchronized hot backups on configurable cadences and enforcing automated retention pruning. Zstandard streaming compression (`.tar.zst`) was integrated as the default snapshot format in `craft-backup`, achieving 3-5x faster compression throughput while magic-byte header auto-detection (`[0x28, 0xB5, 0x2F, 0xFD]` vs `[0x1F, 0x8B]`) guarantees backwards compatibility with legacy `.tar.gz` archives. A sliding-window crash circuit breaker with exponential backoff (`2s -> 5s -> 15s -> 30s -> 60s`) was introduced, tripping to `Open` state after 3 crashes in 60s to prevent infinite restart boot-loops and CPU runaway, with restarts cleanly decoupled across a Tokio channel. All workspace tests and `-D warnings` checks passed cleanly.

### Phase 1: Core Reliability, Safety and Parity
Phase 1 resolved critical operational defects, eliminated irreversible data-loss vectors, and expanded containerization across all 21 server platforms. `craft dockerize` was re-engineered with multi-runtime archetype detection (Java 8/17/21 bytecode matching, Bedrock, Factorio, Terraria, Palworld, Valheim, and Custom) replacing invalid default Java templates. `craft deploy` and the root Dockerfile were upgraded to self-contained multi-stage builds, compiling Craft inside container Stage 1 when pre-compiled host binaries are absent. `craft world rm` was migrated to `TrashManager::trash_path`, ensuring deleted worlds are staged in the recoverable trash bin with SHA-256 manifests unless explicitly bypassed with `--permanent`. `craft fix` was expanded into a self-healing suite handling stale locks, EULA acceptance, port collisions, and native binary permissions. All 138 workspace tests and strict `-D warnings` compiler checks passed cleanly.
