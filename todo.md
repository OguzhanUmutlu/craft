# Craft Roadmap & Phase Tracker (`todo.md`)

This roadmap organizes engineering phases into a strict **Future-Current-Done** lifecycle. Each item is an autonomous phase containing a 5–10 line technical specification outlining its objectives, architecture, prerequisites, and trade-offs. Once completed, phases permanently transition into the Done category.

## Done Phases

### Phase 9: Distributed Multi-Cloud Storage Mesh & Disaster Recovery
Phase 9 delivered a distributed multi-cloud storage mesh, content-addressed rolling chunk deduplication, zero-trust authenticated encryption-at-rest (ChaCha20-Poly1305), and automated disaster recovery (DR) playbooks. A Fast Content-Defined Chunking (`FastCDC`) engine with rolling gear hashing splits game servers and Minecraft Anvil region files (`.mca`) into 64 KB average variable-size chunks stored in a local Content-Addressed Storage pool (`~/.craft/cache/chunks/`) with Zstandard compression, cutting incremental backup bandwidth by over 90%. A pure-Rust RFC 8439 `ChaCha20Poly1305` AEAD cipher with 10,000-round PBKDF2/SHA-256 key derivation secures all stored chunks and signed manifests without external OpenSSL dependencies. A multi-cloud `StorageMesh` coordinator replicates chunks and manifests across AWS S3, Cloudflare R2, Google Cloud Storage, and remote SFTP endpoints with configurable quorum policies (`All`, `Majority`, `Any`). Cryptographic Merkle-tree sampling (`sample_mesh_integrity`) audits chunk integrity without full multi-gigabyte downloads. Disaster recovery commands (`craft dr plan`, `craft dr test`, `craft dr failover`, `craft dr verify`, `craft mesh ls|add|rm|sync|health`) execute automated cold-start recovery simulations in isolated sandboxes (`~/.craft/staging/dr-test-<server>`) and verify zero byte divergence. All workspace unit tests and compiler checks (`-D warnings`) passed cleanly with zero warnings.

### Phase 8: Multi-Tenant Role-Based Access Control, Audit Trails & Web Dashboard

Granular role hierarchies (`SuperAdmin`, `ServerOperator`, `BackupAuditor`, `Viewer`) and fine-grained `Permission` flags are stored in `~/.craft/rbac.toml` with `fs2` advisory file locking (`rbac.lock`), salted 1,000-round SHA-256 password key-stretching, and per-user server scoping (`assigned_servers`). An append-only cryptographic ledger (`~/.craft/audit.log`) records every administrative mutation with continuous SHA-256 hash chaining anchored at `GENESIS_HASH` and pure-Rust HMAC-SHA256 signatures (`verify_chain` detects any line tampering or insertion). A lightweight single-page web dashboard and REST API (`GET /`, `GET /dashboard`, `/api/auth/login`, `/api/servers`, `/api/audit`, `/api/audit/verify`, `/api/rbac/users`) is served directly by `craft-daemon`, featuring authenticated live WebSocket console streaming (`/ws/console`), remote command execution, and real-time server fleet controls. CLI management commands (`craft user add|ls|rm|passwd` and `craft audit ls|verify`) provide operator parity from the terminal. ### Phase 7: Dynamic Resource Optimization, Auto-Scaling & Modpack Distribution
Phase 7 delivered intelligent JVM memory optimization, automated modpack distribution, and packet-triggered auto-scaling with zero-overhead server hibernation. A dynamic memory profile optimizer (`MemoryOptimizer::evaluate`) interrogates host physical memory (`sysinfo`), logical CPU cores, server archetype, and player capacity to compute optimal `-Xms`/`-Xmx` boundaries across Conservative (50%), Balanced (70%), and Aggressive (82%) profiles, selecting Generational ZGC for modern Java 21+ heaps (>=8GB), Aikar G1GC with young-gen tuning, or Shenandoah low-pause flags. A universal modpack engine (`craft_plugins::modpack`) parses Modrinth `.mrpack` (`modrinth.index.json`) and CurseForge server manifests (`manifest.json`), filters client-only dependencies (`env.server == "unsupported"`), parallelizes file downloads with SHA-512 checksum validation and local zstd caching (`CacheStore`), and applies nested `overrides/` and `server-overrides/`. A pure-Rust asynchronous `SleepProxy` TCP service was engineered in `craft-net`, serving custom sleeping MOTD payloads to Minecraft SLP status queries (packet ID 0x00) and intercepting player login handshakes (packet ID 0x00 next_state=2) to immediately emit informative disconnect frames while signaling the supervisor daemon to wake up the server. A background `HibernationManager` reaps idle servers exceeding inactivity thresholds (`idle_timeout_mins`), transitioning their sockets to `SleepProxy` and restoring normal daemon execution upon connection. CLI commands (`craft optimize`, `craft modpack`, `craft autoscale`, `craft hibernate`) provide complete administrative control. All workspace unit tests and compiler checks (`-D warnings`) passed cleanly with zero warnings.

A topological DAG dependency resolution algorithm (`resolve_startup_order`) resolves startup sequences with cycle detection, prioritizing backend/lobby nodes before proxy routers, while `resolve_shutdown_order` enforces reverse teardown. Proxy routing automation (`craft cluster sync-routing`) synchronizes upstream endpoints into Velocity (`velocity.toml`) and BungeeCord (`config.yml`). ### Phase 2: Automated Operations, Backups and Resilience
Phase 2 delivered background automated operations inside `craft-daemon` without external host cron dependencies. An in-process 5-field cron parser and interval evaluator was implemented alongside `DaemonScheduler`, triggering zero-downtime RCON-synchronized hot backups on configurable cadences and enforcing automated retention pruning. Zstandard streaming compression (`.tar.zst`) was integrated as the default snapshot format in `craft-backup`, achieving 3-5x faster compression throughput while magic-byte header auto-detection (`[0x28, 0xB5, 0x2F, 0xFD]` vs `[0x1F, 0x8B]`) guarantees backwards compatibility with legacy `.tar.gz` archives. A sliding-window crash circuit breaker with exponential backoff (`2s -> 5s -> 15s -> 30s -> 60s`) was introduced, tripping to `Open` state after 3 crashes in 60s to prevent infinite restart boot-loops and CPU runaway, with restarts cleanly decoupled across a Tokio channel. All workspace tests and `-D warnings` checks passed cleanly.
